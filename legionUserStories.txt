  ---
  Legion UI User Stories

  Host Management

  US-01 — Add single host
  As a tester, when I open the Add Hosts dialog (Ctrl+H), enter a single IP address, and click Start, a staged nmap scan begins and the
   host appears in the hosts table.
  Pass: host row visible in table; at least one process appears in Processes tab with status Running or Waiting.

  US-02 — Add multiple hosts via semicolons
  As a tester, when I enter 192.168.1.1; 192.168.1.2 in the Add Hosts dialog, two independent parallel nmap scans begin — one per host.
  Pass: two host rows appear; two separate nmap process rows appear simultaneously.

  US-03 — Add host with nmap comma range syntax
  As a tester, when I enter 192.168.85.11,111 in the Add Hosts dialog, the input passes validation and is sent to nmap as a single
  target expanding to both IPs.
  Pass: input accepted without validation error; nmap process starts.

  US-04 — Invalid input rejected
  As a tester, when I enter a string containing shell metacharacters (e.g. 192.168.1.1; whoami with a space before whoami... actually:
  192.168.1.1 | ls) in the Add Hosts dialog, the validation error message appears and no scan starts.
  Pass: red validation message shown; no new rows in Processes tab.

  US-05 — Select host loads its data
  As a tester, when I click a host row in the hosts table, the right panel updates to show that host's services, tools, notes, and
  screenshots. Data from other hosts is not shown.
  Pass: Services tab shows only ports belonging to the clicked host; window title updates to show that host's IP.

  US-06 — Delete host with confirmation
  As a tester, when I right-click a host and select Delete, a confirmation dialog appears. If I confirm, the host and all its
  associated data are removed from the UI and database.
  Pass: host row gone; its ports/processes no longer appear; no confirmation → host remains.

  US-07 — Mark host as checked
  As a tester, when I right-click a host and select the checked/unchecked toggle, the host row's visual state updates to reflect the
  new status.
  Pass: host row styling changes; toggling again reverses it.

  ---
  Scanning & Discovery

  US-08 — Staged nmap runs all 6 stages
  As a tester, when a host is added, stages 1–5 (port ranges) launch simultaneously and stage 6 (NSE/vulners) launches only after all
  port stages complete.
  Pass: up to 5 nmap processes appear as Running at the same time; a 6th nmap process labelled nmap (vulners) only appears after the
  first 5 finish.

  US-09 — Nmap progress percentage shown
  As a tester, during an active nmap scan I can see a percentage progress value updating in the process row every ~5 seconds.
  Pass: % column in Processes tab increments from 0 toward 100 during a scan.

  US-10 — Services appear as nmap discovers them
  As a tester, as each nmap stage completes and imports results, newly discovered ports appear in the Services tab for the selected
  host without requiring a manual refresh.
  Pass: Services tab row count increases as stages finish.

  US-11 — Discovered services trigger automatic tool runs
  As a tester, when nmap discovers an HTTP service, tools configured in SchedulerSettings (feroxbuster, nuclei, nikto, etc.) start
  automatically without any manual action.
  Pass: additional process rows appear in the Processes tab with tool names matching the SchedulerSettings for the discovered service
  type.

  US-12 — Browser refresh does not kill active scans
  As a tester, when I press Ctrl+Shift+R to refresh the browser while a staged nmap scan is running, the scan continues uninterrupted
  and results import correctly after page reload.
  Pass: scan processes are still Running after reload; final results appear in Services tab.

  US-13 — Restarting a scan on a host cancels stale threads
  As a tester, when I delete a host mid-scan and re-add it, the previous scan's threads do not corrupt the new scan's state or import
  partial XML results.
  Pass: only results from the new scan appear; no stale port data from the previous scan.

  ---
  Processes Table

  US-14 — Process table shows tool name, host, status, and start time
  As a tester, each row in the Processes tab displays at minimum: tool name, target host, current status (Waiting / Running / Finished
  / Crashed), and start time.
  Pass: all four fields are populated for any completed process row.

  US-15 — Clicking a process row loads its output in the lower panel
  As a tester, when I click a process row in the Processes tab, that tool's output appears in the lower output panel below the table.
  Pass: lower panel content changes to show the selected process's output; clicking a different row changes the content.

  US-16 — Live output updates while a process is Running
  As a tester, when I select a Running process, the lower output panel updates approximately every 1.5 seconds with new lines as the
  tool produces them.
  Pass: text in the lower panel grows during an active scan without requiring any click.

  US-17 — Scroll position preserved during live output polling
  As a tester, when I scroll up in a Running process's output to read earlier lines, the view stays at my scroll position and does not
  jump back to the bottom on the next poll cycle.
  Pass: after scrolling up, position remains stable across at least 3 poll cycles (~4.5 s).

  US-18 — Auto-scroll to bottom for new output when already at bottom
  As a tester, when I am scrolled to the bottom of a Running process's output panel, new lines appear and the panel automatically
  scrolls down to keep the latest output visible.
  Pass: as output grows, the panel stays at the bottom without manual scrolling.

  ---
  Right Panel — Tab Navigation

  US-19 — Right panel shows Scan, Services, Notes, Screenshot, Brute, Log tabs
  As a tester, after selecting a host, the right panel tab bar displays all expected tabs.
  Pass: Scan, Services, Notes, Screenshot, Brute, and Log tabs are all visible and clickable.

  US-20 — Tab turns orange when new matching data arrives
  As a tester, when a tool process produces output containing a global-positive keyword (e.g. State: VULNERABLE, [+]), the tab
  associated with that tool turns orange to indicate unread findings.
  Pass: the relevant tab has an orange/highlighted style; clicking it removes the orange indicator.

  US-21 — Orange tab indicator persists when switching hosts
  As a tester, when a tab is orange for host A and I switch to host B then back to host A, the tab is still orange for host A.
  Pass: orange state is restored for host A's tab after the host switch round-trip.

  US-22 — Switching to Brute tab and back restores host and process selection
  As a tester, when I am viewing a tool's output, navigate to the Brute tab, then navigate back to the Scan tab, the previously
  selected host row and process output are restored.
  Pass: the same host row is selected; the same process output is shown in the lower panel.

  ---
  Dynamic Tool Tabs (Upper Right Panel)

  US-23 — Running tool opens a dynamic tab in the upper right panel
  As a tester, when a tool process starts for the selected host, a new tab appears in the upper right panel showing that tool's live
  output.
  Pass: tab with the tool's name appears; it shows output that updates while the process runs.

  US-24 — Upper panel scroll position survives tab rebuild
  As a tester, when I scroll up in a dynamic tool tab to read earlier output, the position is preserved across the 1.5-second snapshot
  poll that rebuilds the tab container.
  Pass: scroll position stays stable for at least 3 consecutive poll cycles.

  US-25 — Upper panel font size is independently controllable
  As a tester, clicking the A+/A− buttons in the upper panel tab bar increases or decreases the font size of content in the dynamic
  tool tabs without affecting the lower output panel font.
  Pass: upper tab text grows/shrinks; lower panel text is unchanged.

  US-26 — Lower panel font size is independently controllable
  As a tester, clicking the A+/A− buttons in the lower panel increases or decreases the font size of the process output and log panel
  without affecting the upper dynamic tabs.
  Pass: lower panel text grows/shrinks; upper tab text is unchanged.

  ---
  Services Tab

  US-27 — Services tab lists discovered ports with protocol and service name
  As a tester, after a completed nmap scan the Services tab lists each open port with its number, protocol (tcp/udp), service name, and
   version string if detected.
  Pass: at least one row exists for a scanned host with known open ports; all four fields populated.

  US-28 — Port state filter shows only open ports by default
  As a tester, the Services tab displays only open/open|filtered ports by default, not closed or filtered ports.
  Pass: no rows with state closed or filtered appear in the default view.

  US-29 — Right-clicking a service shows port action menu
  As a tester, right-clicking on a port row in the Services tab shows a context menu of available tools for that service type (filtered
   by the port's service name).
  Pass: menu appears; tools irrelevant to the service type (e.g. SMB tools on an HTTP port) are not shown.

  US-30 — Running a port action from context menu creates a process
  As a tester, when I select a tool from the port action context menu, a new process row appears in the Processes tab for that tool
  running against the selected IP and port.
  Pass: new row with correct host, port, and tool name appears with status Running or Waiting.

  US-31 — Port row turns red when a positive keyword match is found
  As a tester, when a tool run against a specific port produces output containing a global-positive keyword, that port's row in the
  Services tab is highlighted in red.
  Pass: port row styling changes to red/highlighted after the matching tool finishes.

  ---
  CVEs Tab

  US-32 — CVEs tab lists vulnerabilities found by vulners NSE sorted by CVSS score
  As a tester, after the stage-6 vulners nmap scan completes, the CVEs tab for that host lists discovered CVEs with their CVSS scores,
  sorted highest-to-lowest.
  Pass: CVE rows appear; CVSS scores are in descending order; clicking another host shows that host's CVEs.

  ---
  Notes Tab

  US-33 — Notes are editable and saved per host
  As a tester, when I type in the Notes tab and switch to another host then back, my notes for the first host are still there.
  Pass: text entered in Notes persists after host switch round-trip.

  US-34 — Ctrl+B in a terminal tab copies selected text to the Notes tab
  As a tester, when text is selected in an xterm.js terminal tab and I press Ctrl+B, that text is appended to the host's Notes tab and
  the Notes tab turns orange to indicate new content.
  Pass: Notes tab content grows; Notes tab turns orange; selected terminal text appears in notes.

  US-35 — Notes render ANSI colour codes as coloured text
  As a tester, when terminal output containing ANSI colour escape sequences is copied to Notes via Ctrl+B, the notes panel renders the
  text with the corresponding colours rather than showing raw escape codes.
  Pass: coloured terminal output appears with colour in Notes; no literal \x1b[32m strings visible.

  ---
  Brute Force Tab

  US-36 — Brute tab pre-fills username and password from legion.conf defaults
  As a tester, when I navigate to the Brute tab for a host, the username and password fields are pre-populated with the values from
  default-username and default-password in legion.conf.
  Pass: fields not empty on first open; values match legion.conf.

  US-37 — Username field hidden for no-username services
  As a tester, when the Brute tab is active for a service listed in no-username-services (e.g. SNMP, VNC), the username input and
  wordlist fields are hidden.
  Pass: username-related fields not visible; password fields still shown.

  US-38 — Running Hydra from Brute tab creates a process
  As a tester, when I click the Run button in the Brute tab with valid credentials configured, a Hydra process appears in the Processes
   tab.
  Pass: new process row with hydra in the name appears for the correct host and port.

  ---
  Screenshot Tab

  US-39 — Screenshot tab shows eyewitness capture for HTTP services
  As a tester, after the screenshooter runs against an HTTP service, the Screenshot tab for that host displays the captured PNG image.
  Pass: an image is visible in the Screenshot tab; it is not broken/empty.

  ---
  Log Tab

  US-40 — Log tab shows server-side application log output
  As a tester, the Log tab displays Legion's application log lines (tool launches, scan events, errors) captured in the in-memory log
  buffer — without requiring stdout redirection.
  Pass: log lines appear in the Log tab after performing any scan action; the tab is not empty.

  US-41 — Log tab level filter limits displayed lines
  As a tester, when I switch the log level to DEBUG, additional verbose lines (snapshot polling, queue events) appear that were not
  shown at INFO level.
  Pass: line count increases when switching from INFO to DEBUG.

  US-42 — Log tab renders ANSI colour codes as coloured text
  As a tester, log lines that contain ANSI colour escape sequences are rendered with colour in the Log tab rather than showing raw
  escape codes.
  Pass: coloured log output visible; no literal \x1b[ strings shown.

  ---
  Match Indicators

  US-43 — Tool output line matching a global-positive keyword marks the process
  As a tester, when a tool produces a line containing a global-positive keyword (e.g. State: VULNERABLE), the process row in the
  Processes tab is visually marked as a match.
  Pass: process row has a match indicator; clicking the row shows the matching line in output.

  US-44 — Global-positive matching is case-sensitive
  As a tester, the keyword State: VULNERABLE (uppercase) matches tool output containing exactly that string but does not match state:
  vulnerable (lowercase).
  Pass: a process producing lowercase-only output is not marked; one producing uppercase is.

  US-45 — Space-guarded keywords respect word boundaries
  As a tester, the keyword PUT matches a line containing HTTP PUT method but does not match a line containing only the word outputfile
  or INPUT.
  Pass: lines with HTTP PUT is allowed → match; lines with outputfile or INPUT only → no match.

  US-46 — Global-negative keywords suppress a match on that line
  As a tester, a tool output line that contains both a global-positive keyword and a global-negative keyword (e.g. NOT vulnerable) does
   not produce a match indicator.
  Pass: process is not marked as a match when negative keyword is present on the same line as a positive keyword.

  Project Management

  US-47 — Save project writes a .legion file
  As a tester, when I use File → Save, a .legion file is written to the chosen path containing all host, port, service, process, and
  notes data for the current session.
  Pass: file exists on disk; reopening it with File → Open restores all data.

  US-48 — Exiting with unsaved changes prompts to save
  As a tester, when I close the browser tab or navigate away with unsaved project data, a save-on-exit prompt appears before the
  session ends.
  Pass: prompt dialog shown; choosing Save writes the file; choosing Discard exits without saving.

  US-49 — Opening a .legion file restores all hosts and scan data
  As a tester, when I open a saved .legion file, all hosts, ports, services, CVEs, notes, and process history are restored exactly as
  they were when saved.
  Pass: host count, service count, and notes content match the original session after open.

  US-50 — New project clears all current data
  As a tester, when I use File → New, all current hosts, processes, and scan data are cleared and the UI returns to an empty state.
  Pass: hosts table empty; Processes tab empty; Notes tab empty after New.

  US-51 — Window title shows Legion version at startup
  As a tester, when the page loads, the title bar shows LEGION v10.X-flask with the correct version number.
  Pass: title matches the version string in index.html; no hardcoded stale version shown.

  US-52 — Window title updates to show selected host
  As a tester, when I click a host row, the window title updates to include that host's IP and OS guess (if known).
  Pass: title changes from project name to host IP after clicking a host row.

  Config Editor

  US-53 — F2 opens the Config Manager
  As a tester, pressing F2 opens the Config Manager overlay showing the raw legion.conf contents as editable text.
  Pass: Config Manager overlay visible with conf text; pressing Escape closes it.

  US-54 — Ctrl+F / F2 within Config Manager opens find bar
  As a tester, while the Config Manager is open, pressing Ctrl+F opens a find/search bar that highlights matching text in the conf.
  Pass: find bar appears; typing a search term scrolls to and highlights the first match.

  Multi-Instance

  US-55 — Second server on a different port runs independently
  As a tester, when I start a second legion.py --web --port 5001 while a first instance runs on port 5000, both servers operate
  independently with separate projects, processes, and databases.
  Pass: navigating to :5000 shows instance-1 data; navigating to :5001 shows instance-2 data; actions in one do not appear in the
  other.

  US-56 — Each server instance opens its own Firefox window
  As a tester, starting two Legion servers on different ports opens two separate Firefox windows, each pointing to its own server URL,
  with no profile lock conflicts.
  Pass: two Firefox windows open; each shows the correct port in the address bar; neither shows a "profile already in use" error.
